# Arena Edit — Decisions Log

Conservative resolutions of ambiguities in the spec (working rule #4). Each
decision stays valid until superseded; superseded entries are kept with
`SUPERSEDED BY`.

| ID | Decision | Rationale |
|----|----------|-----------|
| D-001 | **Qt Widgets** (not QML) for the UI | Dense NLE layout (docks, custom-painted timeline/monitor), mature UI Automation/Narrator support for the accessibility targets, simple per-monitor DPI, and 120–180 ms motion is fully doable with QPropertyAnimation. QML's retained-mode scene graph is not needed until (if ever) the compositor moves to QQuick items. LGPL-compatible either way; Widgets gives the smaller, more predictable binary. |
| D-002 | **JSON translation catalogs** (allowed by the spec's "or a JSON equivalent") instead of .ts/.qm | Drop-in languages with zero build steps (spec: "drop in a new translation file and it appears automatically"), trivial RTL metadata per locale, no lrelease dependency, and the loader can validate/merge at runtime. Qt Linguist can still be used to *author* translations from the JSON (round-trip is trivial). |
| D-003 | **Cross-platform core, Windows-only targets guarded** | The sandbox/CI here is Linux; the product targets Windows. All Windows-only code (WASAPI, DPAPI, D3D11, registry theme probe, Inno packaging) is behind `Q_OS_WIN` / CI Windows job. Platform-neutral logic (core, i18n, AI client, validator, themer) is verified on Linux with Qt 6.8 in CI; the Windows job verifies the rest. |
| D-004 | **i18n lookup is `translate()`, not `tr()`** | Qt's `Q_OBJECT` macro injects a `static inline tr(const char*, …)` into every QObject subclass when translations are enabled; a member `tr(const QString&)` coexists with it and string literals silently bind to the injected static (returns untranslated text). Verified against Qt 6.8.2. Renaming avoids the trap for all future QObject-based panels. |
| D-005 | **Project extension `.aep`** (JSON content) with schema `v1` | Short, editor-ish, clearly ours; content stays JSON so schema migrations and human diffs work. The optional `.aedit` zip bundle (assets) arrives in M1/M9. |
| D-006 | **AI off by default + one-time privacy notice + per-project budget persisted globally** | Spec: opt-in, privacy notice before first request, ~200 req/h anonymous limit. The budget window (hourly) is stored in settings so the status-bar meter survives restarts. |
| D-007 | **Translator model default = `auto`** | Free model IDs churn; `auto` resolves to the first `:free` model from the live `/models` list, and the user can pin any model from the list (Settings ▸ AI). A pinned model that disappears → the client reports the error and the user reselects; no silent model swap. |
| D-008 | **Reasoning-model streams are surfaced as text** | Real gateway responses (see AI_INTEGRATION.md) show `:free` reasoning models emit `delta.reasoning` with `delta.content: null`. The client appends whichever field is present so "Ask AI" is never blank; the final `finish_reason` (e.g. `length`) ends the stream. |
| D-009 | **Autosave = sidecar file + clean-exit marker** (not in-project versioning) | Simplest crash-safe scheme: `<project>.autosave` written every 60 s while dirty; `<project>.clean` written on clean exit. Launch prompts recovery only when autosave is newer than the project AND no clean marker exists. Both behaviors are unit-tested. |
| D-010 | **Media timeline stays LTR in RTL locales** | Per spec 3.6: time always flows left to right; only text-track content and the rest of the chrome mirror. Implemented by pinning `Qt::LeftToRight` on the timeline widgets while `QApplication::setLayoutDirection` mirrors the app. |
| D-011 | **GTest for unit tests** (per spec) with `gtest_discover_tests` | One test per CI invocation (isolated crashes); CMake zero-config on Debian/Windows vcpkg. |
| D-012 | **FFmpeg/whisper behind CMake options (OFF in M0)** | The skeleton must build without heavy dependencies; M1/M7 flip `ARENA_ENABLE_FFMPEG` / `ARENA_ENABLE_WHISPER`. Interface files (`media/`, `stt/`) define the contracts now and report availability honestly in tests. |
| D-013 | **API key: env var first, then local store (DPAPI on Windows)** | Spec order. The DPAPI path (CryptProtectData) compiles on Windows only; non-Windows dev builds fall back to the plain store file with a logged warning (dev convenience only; shipping targets are Windows). |
| D-014 | **No UPX by default; single portable .exe via static Qt where practical** | Per spec; decided in M9 with the actual dependency set (LGPL Qt shared DLLs staged next to the exe in the portable folder today). |
| D-015 | **`retranslateUi()` must never call `refreshProjectViews()`** | `refreshProjectViews()` ends with `retranslateUi()`; the reverse call created unbounded recursion (stack overflow SEGV) the moment a project existed and the UI retranslated — latent in M0, first hit by M1 auto-project creation on "add clip to timeline". Fix: `retranslateUi()` re-applies the project-specific labels (fps, timecode) directly instead of recursing. |
| D-016 | **Audio output uses the QIODevice sink model with non-blocking writes** | This environment's Qt 6.8 QAudioSink header exposes `QIODevice* start()`, `processedUSecs()`, `bytesFree()` (no `write(QByteArray)` / `processedFrameCount()`). Playback writes through the device returned by `start()` and positions from `processedUSecs()`. The write loop never blocks: it checks `bytesFree()` first and gives up after ~10 s without space, so `stopAudioPipeline()`'s `join()` cannot deadlock on a stalled or consumer-less device. |
| D-017 | **Wall-clock fallback when no audio device exists** | If the sink starts but yields no device (headless CI, machines without audio), playback falls back to the wall clock so video still plays; the audio path is simply absent. `positionSec()` already prefers the sink only when the pipeline is live. |
| D-018 | **Proxy strategy: skip small sources, deterministic cache** | A proxy is generated only when `source height > project proxy height` (default 540). Proxy file name is `proxy_<sha1(path|size)[:16]>.mp4` in the per-user cache dir; a fresh cache entry newer than the source is reused. Proxy failure degrades gracefully to full-resolution playback with a status message. |
| D-019 | **All export output streams use a 1/1000 time base; encoder packets are rescaled before muxing** | The Matroska muxer writes packet pts verbatim into millisecond EBML fields (cluster timecodes and the segment Duration element) — with the encoder time base (1/48000 audio, 1/15360 x264) a 1 s WebM reported 48.312 s (last audio pts in sample units written as ms). MP4 accepts 1/1000 just as well, so one code path covers both containers. Frames are timestamped in the *encoder's* (possibly normalized) time base; packets are rescaled to the *stream's* (1/1000) time base. Verified with an isolated minimal writer: sample-unit pts → 48.312 s, ms pts → 1.008 s. |
| D-020 | **Export runs on a dedicated worker thread with deep-copied job data; fetchers are stateless** | Spec: no UI freezes. `ExportQueue` deep-copies each pending job (project snapshot + settings + fetch lambdas) into the worker at `start()`; the worker never touches shared state. The export fetchers open their own `VideoDecoder`/`AudioReader` per call (never the playback engine, never proxies — full quality). State flows back as queued signals; `Job::state` is only mutated on the UI thread. Cancel is a flag polled per frame. |
| D-021 | **Subtitle data is additive JSON on the project (no schema bump)** | `SubtitleTrack` (id, language BCP-47, name, `burnIn`, `cues`) and `TimelineCue` (startFrame/endFrame in *project frames*, text) serialize as `subtitleTracks` in the project JSON. `fromJson` tolerates the field's absence and a per-track `burnIn`/`cues` absence, so pre-M5 files load unchanged and round-trip cleanly. Cues live in frames (timeline-native); conversion to format seconds happens only at the SRT/VTT/ASS boundary via `secToFrame`/`frameToSec`. |
| D-022 | **Burn-in font is a process-wide default, resolved through fontconfig; tests pin Noto Sans Arabic via a local `FONTCONFIG_FILE`** | Default family is `Arial` (Windows ships an Arabic/Urdu subset, so the RTL goldens work with no bundling). This Linux build's `QFontDatabase::addApplicationFont` is broken (returns 0 for every file, even system fonts), so the burn-in tests write a workspace-local `FONTCONFIG_FILE` that adds the bundled `NotoSansArabic-Regular.ttf` fixture and set it *before* the first font query; if no Arabic-capable font resolves the golden tests `GTEST_SKIP` instead of failing. Burn-in text direction is handled by `QTextLayout`'s built-in bidi (first-strong-character), so there is no per-language layout code. |
| D-023 | **Accept applies the AI title as an undoable project rename; the AI description is shown but never persisted** | The project model (M0/M1) has no description field and no UI surface for it; inventing a schema field for one AI output would violate "resolve ambiguity conservatively". Accept therefore does exactly what has a target: `applyAiTitle` commits `RenameProjectCommand(title)` (undoable, so still user-controlled), and the description remains in the preview/status message for the user to copy wherever they publish. |
| D-024 | **Cut suggestions apply as a video-primary-track-only ripple range delete, one undoable command per cut** | A cut removes a time range from the main video track and ripples the tail forward (`RippleRemoveRangeCommand`); audio/subtitle tracks are untouched (no auto-cross-track sync — that is an editor decision, not the AI's). Applying N accepted cuts runs them in reverse so earlier timecodes stay valid; each is its own undo step. `endFrame` is exclusive, matching the command. |
| D-025 | **Export worker teardown waits (`wait()`) before `deleteLater` to avoid a QThread race** | The M6.2 guismoke exposed a use-after-scope: the worker thread could still be running when `ExportQueue` destroyed it. `onWorkerDone()` now does `wait()` → `deleteLater()` → null the pointer, and the destructor `cancelCurrent()` + `wait(10000)` + conditional `deleteLater()`. No `finished → deleteLater` shortcut (that is the race). |
| D-026 | **SSE line buffer must compare `indexOf('\n') >= 0`, never use the index as a boolean** | `QByteArray::indexOf` returns `0` when the match is at the front (a leading blank line between SSE events), and `0` is false — the old loop silently stopped after the first `data:` line, dropping `finish_reason` and `[DONE]` and misreporting every call as "stream interrupted: incomplete stream" despite HTTP 200. Fixed by draining with a `>= 0` comparison and flushing a stranded tail (no trailing newline) in `finished`. A raw `QNetworkAccessManager` probe confirmed all bytes, including `[DONE]`, arrive before `finished`, so the bug was client-side parsing, not the transport. |
| D-027 | **Per-task `max_tokens` budgets, not one flat cap** | Free-tier models that reason out loud spend the token budget on chain-of-thought *before* emitting the JSON; a flat 1500 truncated the big tasks mid-JSON. `KiloClient::chat` takes an optional `maxTokens` (default 1500 keeps old callers); `aifeatures.h` sizes the four feature budgets from live runs (title 2000, chapters 4000, translate-batch 6000, cuts 4000). |
| D-028 | **JSON extraction keeps the last parseable balanced candidate, not the first** | Reasoning models restate the requested format in their chain-of-thought, sometimes as *valid* JSON (a format template even outlives a short real answer in length). "First candidate" and "largest candidate" both failed on real responses; the model's final answer is always the last structure it emits, so both `extractJsonArray` (actionvalidator) and `extractJsonObject` (aifeatures) scan every balanced candidate and return the last one that parses. Downstream validation remains the safety net. |
| D-029 | **A validation-failed prompt is cache-invalidated before any resend** | The client caches every successful stream, including responses that fail structured validation; a retry of the same prompt then hit the cache and failed identically (and the cache-hit path delivered an empty string because `call->streamed` was never set). Cache hits now deliver the stored content, and the panel/driver call `KiloClient::invalidateCache(system, user)` before resending any prompt whose previous reply failed validation — so "retry the failed batch" actually re-queries the gateway. |
| D-030 | **A cut ending exactly at the video end is valid (exclusive end)** | Cuts are applied as `[start, end)` range deletes, so a tail cut whose end timecode equals the video end removes up to and including the final frame. The validator's `endFrame >= totalFrames` reject was inconsistent with the cut command; it now rejects only `endFrame > totalFrames`. Live evidence: the model copied the trailing-silence map entry verbatim, ending exactly at the video end. |
| D-031 | **Dev tools and tests never mutate the user's real settings profile** | The live driver enables AI + pins a model for the session, and the settings-defaults test asserts a clean profile; both now redirect user-scope INI settings to a `QTemporaryDir` via `QSettings::setPath` *before* `Settings` is constructed (static initializers / global test environment). Previously a driver run left `ai/enabled=true` in `~/.config/ArenaEdit/ArenaEdit.ini` and broke `Settings.DefaultsAreConservative`. |
| D-032 | **STT language is explicit (default `en`); whisper auto-detection is not used** | On whisper.cpp v1.9.5, `detect_language=true` returned **zero segments** (rc=0, language still detected as `en`) for the 11 s `jfk.wav` sample on both tiny and base — verified 2026-10-14 with an isolated driver across four parameter combinations (no_context ±, token_timestamps ±). The app defaults to English and forces the user-facing language; auto-detection stays out until a fixed upstream release is verified. |
| D-033 | **Whisper models are on-demand downloads, size + SHA-256 pinned** | `ensureModel` fetches `ggml-<id>.bin` from `ggerganov/whisper.cpp` (Hugging Face, main) into `AppLocalDataLocation/whisper` (override: `ARENA_WHISPER_MODELS` env, for tests/CI). Pinned 2026-10-14: tiny 77 691 713 B sha256 `be07e048e1e599ad46341c8d2a135645097a538221678b7acdd1b1919c6e1b21`; base 147 951 465 B sha256 `60ed5bc3dd14eea856493d334349b405782ddcaf0028d4b5df4088345fba2efe`; small 487 601 967 B sha256 `1be3a9b2063867b937e64e2ec7483364a79917e157fa98c5d94b5c1fffea987b`. Files are written to `.part`, verified, then renamed; corrupt files are re-fetched. Transcription itself never needs the network. |
| D-034 | **Word spans come from whisper's token-level timestamps; v1.9.x special tokens form an upper-open range** | The C API has no word-level accessors in any checked release (1.6.2–1.9.5); word data = `token_timestamps=true` + `whisper_full_get_token_data/t0/t1` per segment token (centisecs). v1.9.x layout: `whisper_token_beg` (50364) sits *above* `whisper_token_eot` (50257), so the historical `beg ≤ id ≤ eot` range is empty — `[_BEG_]` leaked into words until the filter became `id ≥ beg` plus the individual control tokens (sot/solm/nosp/not/eot). |
| D-035 | **Whisper context is CPU-only by declaration; library log → `arenaLog` debug level** | The build compiles only the CPU ggml backend, so `whisper_context_params.use_gpu=false` is stated explicitly (not left to runtime fallback), and `whisper_log_set` redirects the library's model-load/init chatter to `qCDebug(arenaLog)` — visible with debug logging, silent in the product. Decoded samples accumulate in `std::vector<float>` because Qt 6 `QList`/`QVector` has no pointer-pair `append`. |
| D-036 | **The local STT transcript is in-memory per project, never persisted** | The transcript is a derived artifact of a clip's audio (re-derivable on demand), so persisting it into the `.aep` would bloat the project file and invite staleness when clips change. `AiPanel` keeps it while the project is open and clears it on project switch; the project schema stays at `kSchemaVersion = 1` (no new fields — same conservatism as D-023). |
| D-037 | **NL action contract: `-1` = last clip; marker `time` in project frames; transitions live in `effects.transition` (frames); `export` opens the dialog, never runs** | The model emits indices/times relative to the project context the prompt carries (fps, clip list, duration). `-1` keeps "the last clip" robust to clip counts. `add_marker.time` is integer frames at the project fps (prompt states the rule; the validator only ranges it). `add_transition` stores `{type, duration:frames}` in the clip's `effects.transition` — the exact shape the M3 compositor + exporter already render (a `fade_to_black` on the last clip renders a fade-out with no next clip). `export` is not an undoable edit: applying it opens the export dialog with the preset preselected, and the user still confirms — an NL command must never trigger a long-running encode by itself. |
| D-038 | **Validation at parse, grounding at apply (two gates)** | `aifeatures::parseActions` (extract last-valid candidate + strict schema) gates what the user *sees* in the preview; `MainWindow::applyAiActions` re-checks grounding against the live project (clip index in range, `-1` resolved) and skips anything ungroundable instead of applying it. An unknown op at apply time is a no-op, not an error path. Both gates are unit-tested and smoke-tested (`applyAiActions` is the same public method the preview card's Accept emits into). |
| D-039 | **Sample project = bundled assets copied to the data dir on open (never opened in place)** | `assets/sample_project/` ships `sample-project.aep` + `sample/clip01.mp4` (CC0). `openSampleProject()` copies both into `AppLocalDataLocation/sample_project/` and opens the copy, so the user can save/relink it like any project without write failures on a read-only install. `QFile::copy` refuses to overwrite, so each open removes the previous copy first (guismoke's second run exposed the failure). |
| D-040 | **Reduce-motion disables the tour slide-in, the app's only animation** | There is deliberately no other UI animation (no QPropertyAnimation elsewhere); the 180 ms tour card slide-in is the single motion surface. `Settings::reduceMotion()` on → the card is placed instantly at its final geometry (no tween object started); off → the tween runs. Both branches are guismoke-verified (final position is identical either way). The theme.json `motion.fastMs/slowMs` tokens remain the single source of intent for any future motion. |
| D-041 | **Focus rings = 2 px accent-border QSS on `:focus` (QSS has no `outline`); tour highlight = `tourTarget` property** | Qt Style Sheets cannot express `outline`, so the keyboard focus indicator is a 2 px accent border on all standard controls plus the custom `TimelineCanvas`/`PreviewSurface`/`WaveformStrip`/`ThumbnailStrip`. The rule uses the *user's accent* (never a fixed hue) so re-themed builds keep a 3:1-capable indicator by default (accent #4C8DFF clears WCAG 2.4.7 on all shipped surfaces). The tour reuses the same mechanism: `Tour` sets/unsets the `tourTarget` dynamic property on the target and unpolish/polishes it. |
| D-042 | **Light-theme success green darkened to #177345 for WCAG AA** | The M8 contrast audit (21 fg/bg pairs × 3 themes, `AllThemesMeetWcagAaForTextPairs`) found light `success #1F8A54` on white at 4.36:1 (< 4.5). `#177345` keeps the hue family at 5.87:1. All other pairs already passed; high-contrast theme is 21:1 primary text. |
| D-043 | **`firstRunDone` flips after welcome + tour, not in `main()`** | `main()` used to set `firstRunDone` before `MainWindow` was constructed, so `showWelcomeIfNeeded()` saw `firstRunDone()==true` and the welcome dialog (and now the tour) could never appear on a genuine first launch. The OS-theme detection in `main()` stays (read-only), and `MainWindow::showWelcomeIfNeeded()` now flips the flag after the dialog and starts the tour. |
| D-044 | **M9 verified on the Linux scope; the Windows artifact, signing, and full-media CI build run in the release pipeline (environment boundary)** | This sandbox is Linux-only (no MSVC/Inno Setup/Windows cert), so M9's exit criterion was verified for everything runnable here: packaging layout + staged payloads (CI linux job), installer script (reviewed; `iscc` needs Windows), signing flow (`SignWithSigntoolEnv` + `CERT_PATH`/`CERT_PASSWORD` env), full benchmark harness (cold start/RAM/binary/export FPS in PERFORMANCE.md), and the release docs. Two release-path gaps found and fixed on the way: (1) `ARENA_ENABLE_FFMPEG=ON` was impossible on Windows (the ON path required pkg-config) — added an `ARENA_FFMPEG_DIR` prefix path (standard imported-target pattern, unverified on Windows by the same boundary); (2) `tools/build.ps1` hardcoded FFmpeg OFF with an M1-era comment — now `-WithMedia -FfmpegDir`. The CI windows job is the core-configuration gate (always green); the full-media Windows release build uses `build.ps1 -WithMedia -FfmpegDir <prefix>` where the pipeline provides the FFmpeg dev prefix. |
| D-045 | **App icon: AI-generated, CC0, single 1024 px source; hybrid 8-size .ico; embedded via .rc + .qrc + SetupIconFile** | The icon (2026-10-14, on user request) is AI-generated with no third-party assets, so it is released as CC0 (recorded in THIRD_PARTY.md). One 1024 px PNG is the source of truth; the `.ico` is a hybrid (BMP entries 16–128, PNG 256) because Explorer's small file icons reliably need BMP-format entries while 256 wants PNG. Three consumers, one asset: `app/arenaedit.rc` (exe file icon + VERSIONINFO with the Arena Edit brand and credit; WIN32-only via CMake), `app/app.qrc` (Qt window/title-bar icon from `:/icon/app_icon.png`, verified embedded in the built binary so branding works from any run directory), and Inno's `SetupIconFile`. "Make exe" boundary restated (D-044): no Windows exe is compiled in this Linux sandbox — the icon work makes the Windows pipeline (`build.ps1` / CI) emit the branded exe with zero extra steps. |
| D-046 | **Windows CI imports vcvars64 before release.ps1; vcpkg from the image's C:\vcpkg; MSVC `cl` is not on bare runners' PATH** | The first full release run failed at `Missing tool: cl` — release.ps1's tool check found no compiler because GitHub's windows-2022 runner only exposes MSVC through the Developer environment. Fix: a `shell: cmd` step (`vswhere -latest` → `vcvars64.bat` → `set`) whose output Actions promotes to step environment. vcpkg comes from the image's pre-installed root (`VCPKG_INSTALLATION_ROOT=C:\vcpkg`) with a fresh clone as fallback, since the `lukka/checkout-vcpkg`/`run-cmake` actions no longer exist (repository removed). The vcpkg `ffmpeg` port defaults to LGPL (its `gpl`/`all-gpl` features are opt-in), keeping the release LGPL-only. |
| D-047 | **FFmpeg sample-format lookup is version-guarded in core/ffmpeg_compat.h (7.1+ supported-config API, else static encoder table)** | `avcodec_get_supported_config` + `AV_CODEC_CONFIG_SAMPLE_FORMAT` exist only in FFmpeg 7.1+ (libavcodec ≥ 61.19.100), but Ubuntu 24.04 (CI) ships FFmpeg 6.1.1 while vcpkg (Windows) ships 9.x. The shared header `arena::ff::pickEncoderSampleFormat()` prefers FLTP and falls back to the 20-year-stable `AVCodec::sample_fmts` table on older builds, so one code path compiles and behaves identically across 6.x–9.x (used by the proxy path in media/ and the export path in render/). |
| D-048 | **PowerShell array-literal precedence: `"str" + $(cond)` + trailing comma SPLITs the flag into two argv elements** | `tools/release.ps1` built the CMake args as `@(..., "-DARENA_ENABLE_FFMPEG=" + $(if ($WithMedia) {"ON"} else {"OFF"}), ...)`; in pwsh the comma operator binds tighter than `+`, so the array gained TWO elements (`-DARENA_ENABLE_FFMPEG=` and `ON`) — CMake received an empty-valued flag (=> "FFmpeg explicitly disabled" + media stubs) and a stray `ON` token (the recurring "Ignoring extra path from command line" warnings). Reproduced deterministically with pwsh 7.4.6; fixed by pre-computing the ON/OFF values into variables and using string interpolation (`"-DARENA_ENABLE_FFMPEG=$ffOn"`), which has no operator in the element. Verified: 10/10 args intact. |
| D-049 | **The runner image's pre-installed vcpkg (C:\vcpkg) installs into <root>\installed, not vcpkg_installed** | The GTest find in the release log resolved `C:/vcpkg/installed/x64-windows/share/gtest/` — the image sets its default install root to `C:\vcpkg\installed`. The workflow now detects which root exists (`installed` vs `vcpkg_installed`) before passing `-FfmpegDir <root>\x64-windows`. |
| D-050 | **The FFmpeg-OFF configuration is a first-class, compile-tested build** | `media/ffmpeg_media.cpp` guarded FFmpeg code per-function (`#if !ARENA_HAS_FFMPEG` stub / `#else` real) but left the header includes, the anonymous-namespace helpers, and four member functions unguarded — so the OFF config had never been compiled anywhere (Linux CI always links FFmpeg; the Windows core gate is the OFF configuration and died at C1083). Fix: guard every region that names FFmpeg types at include scope, keep the per-function stubs. `MediaM1` fixture tests gate on `ARENA_HAS_FFMPEG` too — in OFF builds the stubs return false and a *failing* suite would be a false signal; the HonestAvailability tests still pin the OFF behavior. Companion fact: Windows DPAPI (`CryptProtectData`/`CryptUnprotectData` in keystore.cpp) lives in crypt32 — `$<$<PLATFORM_ID:Windows>:crypt32>` on `arena_ai` (PUBLIC). Same lesson as D-047 one layer down: feature boundaries must be expressible in the preprocessor at every layer that touches the feature, not only at call sites. |
| D-051 | **Tests must compile on every CI platform, not just the Linux harness** | The autosave-recovery test set deterministic mtimes with POSIX `utime()` — fine on the Linux harness, but `utime.h` does not exist in MSVC/UCRT, so the Windows core gate (the first Windows *test* build) died at C1083 in tests/test_core.cpp. A second pass was needed: the first fix named `_time64_t` without including `<time.h>` (C2061) and used the 32-bit `_utimbuf` for the 64-bit API (C2664) — MSVC's own error text (`_wutime64(const wchar_t *,__utimbuf64 *)`) gave the exact types; the final helper uses `struct __utimbuf64` with plain assignment (no `_time64_t` name needed) on Windows, POSIX `utime` elsewhere. A tempting shortcut — a Qt-native file-time setter — was checked and does not exist in Qt 6 (no invented-API rule). Lesson: tests compile on every CI platform (both ci.yml jobs), so test-only code needs the same portability discipline as shipped code, and when a compiler reports a signature, copy the types from its own error output. |
| D-052 | **The BurnIn golden suite is Linux-only; ctest gets hard per-test timeouts** | The Windows core gate built in 2 min (84 targets) but ctest test #50 `BurnIn.UrduBurnInGolden` ran 2+ hours with zero output — the job was cancelled at 126 min and the full log pinned the hang in the test, not the build. The suite's font provisioning (fontconfig + bundled Noto Sans Arabic fixture) and its pixel-exact goldens (freetype rasterization) are Linux-environment facts: on Windows the headless `QGuiApplication`/`QFontDatabase::families()` path the suite's own skip-check requires hung, and DirectWrite would rasterize the same font to different pixels regardless. Fix: gate the whole suite (helpers + fixture + 4 tests) behind `#if defined(__linux__)`. Defenses so one stuck test can never hold a runner again: `ctest --timeout 300` in both ci.yml and release.ps1, and `timeout-minutes` job backstops (45 Linux / 90 Windows gate / 120 release). Windows test counts drop accordingly (OFF 104→100, ON 113→109). |
| D-053 | **No Qt GUI application object in headless CI contexts — the constructor itself hangs on the Windows runners** | After D-052 removed the one known GUI-using test, the core gate hung again — and the log showed every `ThemerFixture` test dying at exactly the 300 s ctest timeout. `ThemerFixture::SetUp` called an `ensureApp()` that constructed a `QApplication` (offscreen!) — the themer tests themselves are pure JSON/QSS/color math and never touched a widget. Corroborating pattern: every test that builds a `QImage` without an app passed; every test that constructed a `QGuiApplication`/`QApplication` (offscreen or not) hung for 300 s. So: no GUI app objects in the Windows test binary at all (ensureApp removed), and the app's `--selftest` was restructured into a `QCoreApplication`-only headless core smoke test (no `MainWindow`; window/RTL checks are guismoke's job on Linux).
